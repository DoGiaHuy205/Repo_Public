10. The RTL Module of AXI Stream Wrapper
In the previous section, we learned how to design the RTL modules for the CNN accelerator core.
Now in this section, we will integrate this core with the Zynq ARM processor.
The image pixels will be stored in the DDR memory and sent to the accelerator core for processing.
Then, we will use the Xilinx AXI DMA IP core to interface the accelerator with the DDR memory system.
To achieve this, we need to develop a top level or wrapper module that enables our accelerator core to communicate using the standard AXI stream protocol.
Currently, the input to the accelerator core is already in a stream, so all that needs to be done is to implement the handshaking signals of the AXI stream protocol.
An AXI stream module typically has two sides, an input side and an output side.
Each side transmits data in only one direction.
In our example, the input refers to the image pixels sent from the AXI DMA to our core, while the output is the prediction result sent from our core back to the AXI DMA.
Each AXI stream interface consists of the following mandatory signals: ready, data, valid, and last.
On the input side, the ready signal is driven by our accelerator and sent to the AXI DMA, indicating that our core is ready to accept data pixels.
Data transfer occurs when both the ready and valid signals are high (logic 1).
When our core has received all the input pixels, it deasserts the ready signal, sets it to zero, signaling the AXI DMA to stop sending data and thus preventing data loss.
The ready signal will go back to one after our core finishes the computation.

First, the data signals are fed into a pipeline register and then passed to the convolution 1 module.
Then, we have a finite state machine implemented using a counter based sequencer.
The counter starts on the rising edge of the valid signal, so a rising edge detector circuit is also included.
When the counter reaches a certain value, we assert or deassert the ready signal and the internal valid signal for the convolution 1 module.

The last signal indicates the final data of the stream packet.
Since we only have one data item, we assert last at the same time as the valid signal.
